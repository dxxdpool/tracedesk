## Problem

Since the latest refactor, a brand-new shopping cart sometimes already contains items a different customer added. Totals come out too high for the second customer, and the test suite has started failing.

## Root cause

**In cart/cart.py, new\_cart uses a mutable default items=\[\] so every cart created without items shares one list; add appends into that shared list, so a brand-new cart inherits an earlier customer's items and its total is too high.**

Verified (`a7ecd262`) by:

- experiment `b595584a`: `python -m pytest -q tests/test_cart.py::test_new_carts_start_empty` approved by human, exit code 1, outcome `confirms`

Supporting evidence:

- `cart/cart.py:4-6`: new\_cart declares items=\[\] as a default, so the same list object is reused by every call that omits items. (by investigator)
- `cart/cart.py:9-14`: add mutates cart\['items'\] in place with append, so items land in the shared default list. (by investigator)
- `tests/test_cart.py:5-9`: Test expects a second new\_cart to start empty while the first cart keeps its item; the shared default breaks this. (by investigator)
- commit `1eea0537a463` in `cart/cart.py`: Refactor replaced the None default plus 'if items is None: items = \[\]' with a bare mutable default items=\[\]. (by investigator)

```
def add(cart: dict, name: str, quantity: int = 1) -> dict:
    """Add `quantity` of `name` to the cart and return it."""
    if quantity < 1:
        raise ValueError("quantity must be at least 1")
    cart["items"].append((name, quantity))
    return cart
```

```
def discounted(total_cents: int, percent: int) -> int:
    """Total after a percentage discount, rounded down to whole cents."""
    if not 0 <= percent <= 100:
```
